# Заметки по проекту (для продолжения работы в новой сессии)

## Что это
Новый сайт median.agency по дизайну и ТЗ 2019 года (TZ_site_median.pdf в Google Drive, папка Median_site).
Статика без сборки: `index.html` + `css/style.css` + `css/fonts.css` + `js/main.js` + `fonts/` + `media/`.
Деплой: GitHub Pages через Actions при пуше в `main`. Адрес: https://nazyrovruslan.github.io/median-site/

## Правила работы
- Правки готовить локально, показывать, что изменилось; пушить/деплоить только по явной команде Руслана.
- После правок в CSS/JS поднимать номер `?v=` у подключений в `index.html`, иначе GitHub Pages до 10 минут отдаёт браузеру старый файл из кэша.
- Шрифты: заголовки Druk Wide Cyr Bold (700) и Medium (500), текст Basis Grotesque Pro 400/500/700 (с 05.10, замена Euclid по просьбе Руслана; .woff2 сделаны из его .ttf). Лежат в `fonts/`.
- Заголовки разделов — переменная `--h2`; контурные слова — класс `.o` (text-stroke).
- Сетка десктопа (≥821px) как в макете median_site 2.ai: поля `--gutter` = 1/12 ширины, между ними 5 колонок по 1/6 (на 1920: 160 + 5×320). Шапка и баннер используют свои поля `--pad`. Кегли на 1920: заголовки 95px (`--h2`), крупный текст 38px (`--lead`), карточки 17px (`--txt`), подписи 18px (`--ui`).

## Страница кейса (панель `#casePanel`)
Обложка — во весь экран, как в прошлом варианте (решение Руслана 04.10): фото на фоне, внизу «Кейс», заголовок (строки сплошные/контурные), подзаголовок, направление и год, круг со стрелкой. Дальше по макету (артборды 14, 21–23, 25) → факты (лого клиента, Категория/Клиент/Локация/Год/Формат/Услуги/Сайт, лид) → серые секции → «Следующий проект» (фото по центру, линия прогресса; на полном прокруте фото улетает на место фото обложки следующего кейса).
Данные — `content/cases/<id>.json` (по файлу на кейс, правятся через CMS `/admin`); `js/cases.js` из них собирает `node tools/build-cases.mjs` — сам файл не править, перезапишется. Секции `blocks`: `cut` (вырезанное фото + текст), `pairs` (три фото с контурными словами), `feature` (заголовок + фото + белая карточка), `text` (заголовок + текст на колонках 3–5), `stats` (цифры). `img` — фото обложки, `vid` — видео-обложка (`media/video/<id>.mp4` h.264 + `<id>.hevc.mp4` для браузеров с HEVC — если HEVC не меньше, там лежит тот же h.264; постер `<id>.webp` — статичная заглушка со старого median.agency; ≤1280px без звука; при загрузке страницы прелоадер из макета (знак median заполняется сверху вниз) скачивает все видео в память, не дольше 15 с; на видео-обложках нет наезда, заголовок баннера инвертируется (mix-blend difference); «Альфа Движ» дорисован с 15 до 30 кадров/с; играет в баннере и на обложке кейса только видимое, при «уменьшении движения» — фото), `light:1` — светлое фото (тёмный заголовок в «Следующем проекте»).
Kaspersky — полностью по макету, фото вытащены из .ai (`media/cases/`). Фото остальных кейсов lp.median.agency скачаны с Тильды (static.tildacdn.com), в webp: обложка `<id>-cover` (1920px), коллажи `pairs` без слов (`<id>-<n>-<k>`, 1280px), один короткий текстовый блок превращён в `feature` (`<id>-feature`). Без фото: MegaFon, WG Awards, Grid Girls (их нет на lp; median.agency с просроченным SSL не открывался), у VTB только обложка из макета.
Адрес кейса: `/<id>` (например `/median-site/southhub`); прямые ссылки отдаёт `404.html`, он передаёт путь главной через sessionStorage. Старые ссылки `?case=<id>` тоже работают (id из `CASES`). Открытие и переход к следующему кейсу добавляют запись в историю; «назад» и крестик возвращают к предыдущему кейсу или на главную; по прямой ссылке кейс открывается сразу.

Видео-обложки взяты со старого median.agency (`wp-content/uploads`, SSL просрочен — качать с `curl -k`): alfa-dvizh, southhub, alfa-battle, megafon, vtb, kaspersky, wg, gridgirls. YouTube облачному серверу отдаёт капчу (google.com/sorry), Kinescope отдаёт плейлист, но CDN kinescopecdn.net закрыт.

## CMS (с 2026-10-04)
- Редактор: https://nazyrovruslan.github.io/median-site/admin/ — Sveltia CMS (совместима с Decap), настройки `admin/config.yml`. Правит `content/cases/*.json` и грузит файлы в `media/cases` (фото → webp автоматически) и `media/video`. Каждое сохранение — коммит в `main`.
- Вход: «Sign In with Token» → GitHub fine-grained token: github.com/settings/personal-access-tokens/new → Repository access: Only select → median-site → Permissions: Contents — Read and write → Generate. Токен хранится только в браузере.
- Деплой (`.github/workflows/pages.yml`): `tools/build-cases.mjs` собирает `js/cases.js` (порядок — поле `order`, первые 5 — баннер), `tools/media.mjs` досоздаёт недостающие производные (HEVC и постер видео-обложки, превью 520 px в `media/thumb`, постер и тизер ролика кейса), всё это коммитится обратно в main с `[skip ci]`; версия `cases.js?v=` на сайте = хэш коммита.
- Локально после правок в content/: `node tools/build-cases.mjs && node tools/media.mjs`. Поле `reel` теперь путь к mp4 (раньше флаг 1).

## Страница ошибок
`404.html` — одна страница на все ошибки. GitHub Pages отдаёт её на любой несуществующий адрес. Адреса кейсов и /about она не считает ошибкой и перенаправляет на главную (кейс откроется). Другие коды: `404.html?code=500` (400, 401, 403, 408, 410, 429, 500, 502, 503, 504) — пригодится, если сайт переедет на свой сервер.
